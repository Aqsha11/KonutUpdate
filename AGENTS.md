# AGENTS.md

**Konut Update** — Laravel 12 news portal (Indonesian, Konawe Utara). Bootstrap-style, no modules/packages of its own.

**README.md is unreliable.** Verified wrong claims: headline limit is **6** (`Post::enforceHeadlineLimit`), not 9/unlimited; there is no Cropper.js client-side crop and no "headline keeps original size" exception; the `posts` columns/status list is outdated. Trust `routes/web.php`, `app/`, and migrations.

## Architecture

- **Single route file**: `routes/web.php` (includes hand-written `robots.txt`, `/feed`, `/sitemap.xml`, `/sitemap-news.xml` closures). Article detail is the root-level catch-all `GET /{slug}` (slug regex `[a-z0-9\-]+`) at the **very end** of the file — Laravel matches routes in registration order, so a new root-level route must be added **above** that block. `GET /berita/{slug}` is a 301 legacy redirect to it. Comment/like POST endpoints deliberately stay under `/berita/{post}/...`. Public author profiles live at `GET /penulis/{slug}` (`authors.show`) — also above the catch-all.
- **Mobile API** lives in `routes/api.php` (`/api/v1/*`, read-only, registered in `bootstrap/app.php` with `apiPrefix: 'api'`) with controllers in `app/Http/Controllers/Api/V1` and `app/Http/Resources/*`. Every list endpoint wraps payloads as `{success, data, meta, links}` and caps `per_page` at 50. Tab beranda aplikasi punya feed sendiri di `FeedController`: `/latest` (non-opini), `/trending` (urut `views_count`), `/opini` (hanya `type=opini`), `/featured` (scope `featured()` = 14 hari) — semuanya paginasi. Category data **must** go through `Category::allPosts()` (pivot) and `allPosts as posts_count`, not the legacy `Category::posts()` (FOREIGN KEY `category_id`). `tests/Feature/ApiV1Test.php` smoke-tests all endpoints.
- **A route can never shadow a file in `public/`**: `artisan serve` (also used in production by `render.yaml`) runs the framework's `server.php` fallback (there is **no** root `server.php` in this repo), which serves any existing `public/` file directly without booting the framework. A route at `/manifest.json` is therefore dead code while the file exists. Corollary for tests: `$this->get('/manifest.json')` 404s in the test client (it hits the routes), so read `public_path('manifest.json')` from disk instead.
- **Controllers**: `app/Http/Controllers/{Admin,Frontend,Auth}`. Validation lives in `app/Http/Requests/{Store,Update}*` FormRequests, not in controllers.
- `Auth\LoginController` renders the **admin** login view (`admin/auth.login`) for *everyone* — there is no separate public login page.
- `admin` routes run `['auth','admin','admin.session-timeout']`; `bootstrap/app.php` aliases `admin`, `role`, `permission`, `admin.session-timeout` and appends `SecurityHeaders` to every web request.
- `app/Repositories/PostRepository.php` is the real frontend query layer (headline/trending/category/kecamatan structures); `HeadlineService` is a thin wrapper. Go here before adding query logic to a controller.
- **Dead code**: `app/Http/Controllers/Contributor/*`, `resources/views/contributor/*`, and `StoreContributorPostRequest` are orphaned — the `/panel-kontributor` routes were deleted (only a 302 to `/profil` remains). Don't wire them back up; the opinion flow now lives in `Frontend\OpiniSubmissionController` + the profile page. Likewise `Admin\TagController` + `resources/views/admin/tags/*` + `StoreTagRequest`/`UpdateTagRequest` have **no routes** (tags are entered as free text in the post form via `Tag::firstOrCreate`); the `/admin/tags` row in `README.md` is fiction.

### Data model
- `posts` holds all content via `type`: `article`, `video`, `opini`.
  - Gotcha: the column migration declares only `['article','video']`; `opini` was added later **only as a raw pgsql CHECK constraint** (`2026_08_15_000002`). So `type='opini'` works on SQLite but has no local DB enforcement.
- `status`: `draft`, `pending`, `published`, `rejected`. Contributor/opinion submissions land as `pending`; admin approve/reject sets `status` + `rejection_reason`.
- `category_id` is legacy. Use the `post_categories` pivot via `Category::allPosts()` / `$post->categories()`. `Category::posts()` (HasMany on `category_id`) still exists — don't use it.
- `is_headline` and `is_featured` are **independent** columns (renamed apart in `2025_07_26`, then `is_featured` re-added in `2026_08_15`). Don't conflate them.
- **Max 3 categories per post** — controllers hard-slice with `array_slice($categoryIds, 0, 3)` (requests also cap `category_ids` at `max:3`).

### Roles & auth
- Roles: `super_admin`, `editor`, `reporter`, `kontributor`, `pembaca`. `User::hasPermission()` short-circuits `true` for `super_admin`.
- Admin opini routes are gated by `permission:manage_opini`; `/admin/users` + `users/{user}/verifikasi` require `role:super_admin` (role changes are done there).
- Controller-based auth, **not** Breeze/Jetstream. `User` implements `MustVerifyEmail`; only `super_admin` may log in unverified. Registrasi umum membuat role `pembaca` (`Role::firstOrCreate` in `RegisterController`, so it works on an unseeded DB). Nobody gets `kontributor` automatically — a super_admin must change the role in `/admin/users`.
- Kontributor tetap ada sebagai penulis, tetapi **panel `/panel-kontributor` dihapus** (302 → `/profil`); kontributor kini memakai halaman profil publik dan hanya bisa mengirim **opini** (sama seperti pembaca). Login/verifikasi kontributor mendarat di `/profil`.
- `AdminSessionTimeout` hardcodes 5 idle minutes (`$idleMinutes = 5`, not env-driven) and short-circuits for non-admin roles (`pembaca`/`kontributor` never auto-logout).
- **Public profile** (`/profil`, `Auth\ProfileController@index`, view `frontend/account/index.blade.php`) is shared by `pembaca` + `kontributor`, IG-style: avatar + recap counts (`published`/`pending`/`rejected`) + tab "Kiriman Saya" (all of the user's `posts`, filter `?filter=`, paginated 10) + tab "Edit Profil" (avatar/nama/email/password). The "Kirim Opini" modal posts to `POST /kirim-opini` (uses CKEditor via `window.initCKEditor` in `resources/js/app.js`, uploads to `/kirim-opini/upload-image`). `GET /kirim-opini` now just redirects to `/profil?opini=1` (auto-opens the modal). `admin` roles still go to `admin.profile.index`.
- `TRUST_PROXIES` is only set in `render.yaml`, **not** in `.env.example` — set it manually if you reverse-proxy locally.

### Turnstile (read this before touching auth)
- Login/register/reset/resend/verify POSTs validate `cf-turnstile-response` via `App\Rules\Turnstile`. The config key is `services.turnstile.enabled` = `env('TURNSTILE_ENABLED', true)` — the **default is on**, and it is now explicitly on in `.env`, `.env.example`, and `.env.production`. **Never set it false in production.**
- **Dummy keys have two different lengths** (Cloudflare): site key `1x00000000000000000000AA` (22 char) vs secret key `1x0000000000000000000000000000000AA` (35 char). Putting the *site* key in `TURNSTILE_SECRET_KEY` makes siteverify answer `invalid-input-secret` ⇒ **every login/register fails**. The dummy secret only accepts the dummy token `XXXX.DUMMY.TOKEN.XXXX` produced by the dummy widget. `tests/Feature/LoginTurnstileTest.php` locks both values in `.env`/`.env.example`.
- **Production secret**: `.env.production` intentionally keeps `TURNSTILE_SECRET_KEY=` empty (that file is tracked in git). The real secret must be set in the **Render dashboard** — `render.yaml` declares `TURNSTILE_SECRET_KEY` and `GEMINI_API_KEY` with `sync: false` so a blueprint sync never wipes them. Without the secret, `TurnstileService::verify()` returns `false` (fail-closed) and the service logs an error with a hint.
- When disabled, the rule/service short-circuit to pass, the controllers drop `required`/`string` from the rule set, and `partials/turnstile.blade.php` renders nothing (no widget, no Cloudflare script — so no outbound call).
- When enabled, the widget partial renders only if `TURNSTILE_SITE_KEY` is set, but the rule runs regardless. Empty keys ⇒ `TurnstileService::verify()` returns `false` ⇒ every login/register fails.
- Local dev uses Cloudflare's always-pass dummy keys (see above) — the widget renders and verification makes a real outbound call to `challenges.cloudflare.com` (dummy secret ⇒ always passes).
- Tests: `phpunit.xml` pins `TURNSTILE_ENABLED=true` so the enabled-path tests still run; disabled-path tests toggle `config(['services.turnstile.enabled' => false])`. Enabled tests **must** `Http::fake()`; see `tests/Feature/LoginTurnstileTest.php`.

### Helpers & rendering
- `app/Helpers/helpers.php` is loaded via `require_once` in `AppServiceProvider::register()` — not composer autoload. Adding a helper file means editing that call.
- `setting($key)` caches per-key forever; `clearSettingCache()` clears `site_settings` + per-key entries. Call it after writing settings.
- `HtmlSanitizer` whitelists CKEditor `body` HTML; controllers call it before persisting, and views print with `{!! !!}`. **The sanitizer is the only XSS defense** — never skip it, and never widen `allowedTags`/`allowedAttributes` casually.
- `seoInternalLinks()` auto-links the first occurrence of each keyword in article bodies (skips `<a>`/`<pre>`/`<code>`/`<script>`/`<style>`).
- `SecurityHeaders::buildCsp()` hardcodes the CSP allowlist. Adding a new external embed/CDN (a new video host, a font, an analytics script) requires editing it or the browser blocks it silently.
- **Favicon/icon are static and must stay opaque.** Apple silently rejects transparent PNGs for `apple-touch-icon`, and Android `maskable` icons need a full-bleed background. The assets in `public/icons/` + `public/favicon.ico` were pre-rendered from `public/logo/logo KU.png` on white with ~18–40% padding (logo fills the maskable safe zone); don't regenerate them from the transparent source. The `favicon` site setting is **no longer read** by the frontend — the `<link>`s point at the bundled files unconditionally, and `public/manifest.json` is plain static. `tests/Feature/FaviconFallbackTest.php` locks this, including that every declared `sizes` matches the real pixel size of the file it points to.
- **All page metadata lives in one partial**: `resources/views/frontend/partials/seo-meta.blade.php` (description, robots, OG, Twitter). Views supply values via `@section('seo_title'|'seo_description'|'seo_type'|'seo_robots'|'seo_image'|'seo_image_alt'|'seo_image_width'|'seo_image_height')` and the layout emits exactly **one** `<link rel="canonical">` (`@yield('canonical', $__canonical)`) plus `@yield('json_ld')`. There is **no** `@section('meta')` and **no** `share_image` anymore — if you need a new meta tag, add it to the partial, not to a view.
  - **Blade gotcha:** read those sections with the `seoSectionValue()` helper (`app/Helpers/helpers.php`), not `@yield` — `@yield` inside a `@php` block is not compiled, and `Blade::startSection($section, $content)` escapes its content (`&` → `&amp;`), so the helper decodes once to avoid double escaping. `$__env` is not reliable inside view closures in Laravel 12.
  - `og:image` = `@section('seo_image')` → fallback to the `logo` setting → `/og-default.jpg`.
- **Public sitemap/robots**: `/sitemap.xml` (cache key `sitemap_xml`, 1h), `/sitemap-news.xml` + alias `/news-sitemap.xml` (cache key `sitemap_news_xml`, 15m, articles ≤ 2 days, max 1.000), `/robots.txt` (lists both sitemaps). All three are closures in `routes/web.php` and must be invalidated in every admin write path (`Admin\PostController`/`OpiniController`/`VideoController` → `forgetFrontendCaches()`, `Admin\PageController`/`CategoryController` → `Cache::forget('sitemap_xml')`).
- **SEO columns on `posts`**: `author_id` (link to the public writer profile), `author_name` (free-text byline), `image_alt` (alt text, falls back to the title), `content_updated_at` (honest `dateModified` — only bumped when the body/title/excerpt really changes), `duplicate_of_id` (marks a copy). A post with `duplicate_of_id` is automatically `noindex, follow` and is excluded from both sitemaps (`Post::scopeNotDuplicate()`). `Post::duplicateCandidates()` suggests similar titles (PHP `similar_text`, threshold 0.85) in the admin form — advisory only.
- **Author profiles**: `users.slug` (unique) + `users.bio`; `GET /penulis/{slug}` renders `frontend/authors/show.blade.php` with `Person` + `BreadcrumbList` JSON-LD (noindex when the author has no articles).
- `public/sw.js` (service worker) is registered by the frontend layout and caches pages/images in versioned buckets (`konut-update-v10`, …). Bump `CACHE_NAME` when you change it, or users keep the stale bundle. In dev, unregister it to avoid serving cached HTML.

## Domain gotchas

- **Homepage hero fallback**: `HomeController::index()` fills the 4 hero side slots with the newest non-headline articles, but the hero block is only rendered when a valid headline exists (`@if($heroMain)`). If there is no valid headline the filler articles must **not** be consumed (`$usedIds`) — otherwise the 4 newest posts vanish from the homepage entirely. `tests/Feature/LikeStateTest.php` covers the downstream symptom (like state + post visibility).
- **Headline** (`is_headline`, 7-day `headline_expires_at`) is excluded from "Berita Terbaru" and trending via `scopeExcludeHeadline`. Cap is 6, enforced by `Post::enforceHeadlineLimit($keepId)` — it silently revokes the oldest headline flag. Only Admin `PostController`/`OpiniController` call it (store + update = 4 call sites); Video (`Admin\VideoController`, plain `Request`) and the opinion-submission flow never accept `is_headline`, so add enforcement there if you ever expose the field.
- **`is_featured`** ("Konten Pilihan") expires 14 days after `published_at` (`Post::FEATURED_EXPIRE_DAYS`). `scopeFeatured()` hides expired rows immediately; `posts:expire-flags` clears the flag. Re-saving an old post in admin re-arms it from scratch. `is_breaking` works the same way with a 3-day `breaking_expires_at` (set on store/update, cleared by the same command).
- **Frontend caching** lives in `AppServiceProvider` view composers: `site_settings` (forever), `frontend_pages` / `trending_posts` / `frontend_categories` / `frontend_kecamatans` / `frontend_ads` (1h), `breaking_news` (5m). The composer data is computed **once per request** (`AppServiceProvider::sharedFrontendData()`) and `Schema::hasTable()` is memoized per request (`tableExists()`) — without that memo the `View::composer('*')` fires ~80 metadata queries per page. Cache invalidation is split by writer: admin Post/Opini/Video controllers call their private `forgetFrontendCaches()` (clears `trending_posts`, `breaking_news`, `frontend_categories`, `frontend_kecamatans`, `sitemap_xml`, `sitemap_news_xml`), `Admin\PageController` clears `frontend_pages` directly, `Admin\AdController` clears `frontend_ads`, `Admin\KecamatanController` clears `frontend_kecamatans`, `Admin\SettingController` calls `clearSettingCache()`. If you add a cached query, wire up its forget at every write site or the UI goes stale.
- **Images**: Intervention Image 3 instantiated inline as `new ImageManager(new Driver)` (GD) — there is no `config/image.php`. All output is WebP 85%. Post/Opini/Video/contributor thumbnails are unconditionally `cover(1200, 675)` (no headline exception). Inline CKEditor uploads use `resizeDown(1200)`. Avatars are `cover(400,400)`.
- **Video**: `video_path` may be a YouTube/Vimeo/TikTok URL or an uploaded file. `video_url` / `video_embed_url` / `video_poster` / `is_tiktok` accessors handle the branching. `fetchVideoThumbnail()` (helpers) makes **real outbound HTTP** to YouTube/TikTok oEmbed — guard it in tests.
- **Story**: own `stories` table (not a post type) — `title` **derived from the selected `category_id`** (admin picks a category; `StoryController` stores `title = category->name`), required `image`, optional `url`, `is_active`, `sort_order`, and `expires_at` set to `now()->addDays(Story::EXPIRE_DAYS)` (=7) on create. Display title comes from `Story::display_title` (`category?->name ?? title`), so category renames reflect immediately and `nullOnDelete` keeps the last-known name. **No count cap** (unlike headline). `Story::scopeActive()` + `scopeSorted()` render it as a ring strip **above the headline** on the homepage only (`HomeController::index` eager-loads `category` and queries it directly — *not* cached, so no `forgetFrontendCaches` needed in `Admin\StoryController`). Image is stored via `resizeDown(1080, 1920)` (aspect-preserving, no crop) in `stories/`; admin `extend` re-arms expiry + reactivates, `toggle` flips `is_active`. Frontend uses the `storyViewer` Alpine component (`resources/js/components/storyViewer.js`) — fullscreen viewer with 6s auto-advance, tap/arrow nav, hold-to-pause; story data is passed through `data-*` attributes, never inline JSON.
- **Views/comments/likes are IP-keyed, not auth-keyed.** `RecordViewJob` dedupes per IP for 10 min and stores an anonymized IP (last octet zeroed).
- **AI chat ("Tanya Berita")**: public RAG over published posts, no embeddings/vector store. Tamu mendapat jatah **pertanyaan gratis terbatas** (`services.gemini.guest_limit`, env `GEMINI_GUEST_LIMIT`, default 2) yang dihitung per IP (TTL 1 hari). Setelah jatah habis, endpoint mengembalikan `403` dengan `requires_auth: true` dan UI menampilkan ajakan Masuk/Daftar. User terautentikasi tidak mengkonsumsi jatah tamu dan tetap tunduk pada rate limit `ai-chat` (10/min + 100/day) serta `services.gemini.daily_limit` (cache counter, default 1000, 0 = off). `POST /tanya-berita` (`Frontend\AiChatController@ask`, middleware `throttle:ai-chat`) → `AiChatService` → `PostRepository::searchForChat()` (keyword + PHP scoring, published-only; portable `LOWER(...) LIKE` so it works on both sqlite and pgsql) → Google Gemini `generateContent` via `Http`. `sources` are built from the DB (not from model text); the answer is rendered **escaped** (`x-text`), never `{!! !!}`. Gemini runs **server-side**, so **no CSP change is needed** — do NOT add googleapis to the allowlist (`SecurityHeaders::buildCsp()` `connect-src` already allows only `'self'` + turnstile + open-meteo). Gated by `config('services.gemini.enabled')` (env `GEMINI_ENABLED`, default true) + a non-empty `GEMINI_API_KEY`: widget hidden and endpoint 503 when the key is missing. The model is `GEMINI_MODEL` (default `gemini-2.5-flash`) with a comma-separated `GEMINI_FALLBACK_MODELS` chain (default `gemini-3.5-flash,gemini-flash-latest,gemini-2.5-flash-lite`) tried on any non-2xx — Google retires models. The system prompt is deliberately **not** article-only: a **panduan** file (`resources/ai/panduan-konut-update.md`, loaded by `App\Services\AiGuide`) is injected into the `systemInstruction`, so procedural questions ("cara daftar akun", "bagaimana kirim opini", ...) are answered with numbered steps straight from that file. **That guide is the source of truth** — when a public flow changes, update the guide (and `AiGuide::links()` for the source chips) or the AI keeps answering the old way. Gemini is called even when no article matches (previously it short-circuited with "tidak menemukan berita"); `sources` then holds guide links (category `Panduan`) picked by keyword instead of articles. **No captcha on this endpoint** (Turnstile is only used for auth): abuse is bounded by the per-IP limiter `ai-chat`, `question` max 300 chars, and the global daily budget cap. Frontend: `resources/js/components/floatingHub.js` (Alpine) + `partials/floating-hub.blade.php`, included in the frontend layout. It's a **single FAB (bottom-right) that expands into a menu** — "Tanya Berita AI" + "Masuk/Daftar" (or "Akun Saya"/"Keluar" when authenticated). Untuk `pembaca`/`kontributor`, menu tambahan **"Kirim Opini"** ditampilkan dan "Akun Saya"/"Profile" mengarah ke halaman profil publik `/profil` (bukan dashboard). Login and chat share one bubble; a one-time teaser (`localStorage` key `ku_hub_teaser_seen`) advertises the AI chat to visitors. Chat panel has two close actions: **minimize** (keeps the conversation, shows a badge on the FAB while it has messages) and **end** (clears the history, with an inline confirm) — `minimizeChat()`/`requestEnd()`/`endChat()` in `floatingHub.js`.
- Local DB is SQLite (`.env`, `.env.example`); prod is **pgsql** (`render.yaml`). Migrations that use raw `ALTER TABLE ... ADD CONSTRAINT` are pgsql-guarded — keep that guard if you add one.
- Rate limits: login 10/min/IP, register 5/min/IP, password reset 5/min, comments 5/min, likes 30/min, verification 6/min, ai-chat 10/min + 100/day.

## Testing

- `RefreshDatabase` + factories; `phpunit.xml` forces `:memory:` SQLite, `array` cache/session, `sync` queue, and dummy `TURNSTILE_*` keys.
- Roles are created inline — `Role::factory()->create(['slug' => 'editor'])` — then permissions attached via `$role->permissions()->attach(...)`. `UserFactory` emails are verified unless you use the `unverified()` state.
- `tests/Feature/SmokeSeedTest.php` is the exception: it calls `$this->seed()` (full `DatabaseSeeder`, Faker-driven) and smoke-renders `/`, `/berita/{slug}`, `/kecamatan/{slug}`, `/semua-berita`, `/terkini`, `/trending`. Run it after touching frontend queries or views — it's the cheapest regression net here.
- `UserSeeder` hardcodes `role_id` 1/2/3 (super_admin/editor/reporter) and depends on `RoleSeeder` inserting in that exact order. Don't reorder or renumber roles.
- `fetchVideoThumbnail()` and Turnstile verification hit the network — fake `Http` in any test that touches them.
- SEO regressions are covered by `tests/Feature/SeoMetaTest.php`, `SitemapTest.php`, `NewsSitemapTest.php`, `RobotsTest.php`, `AuthorProfileTest.php`, `DuplicateContentTest.php`, `LikeStateTest.php` (all offline).
- `tests/Feature/PublicProfileTest.php` also covers the **opini submission** (`POST /kirim-opini`): post created as `type=opini`/`status=pending`, slug unik untuk judul kembar, dan validasi `body` minimal 50 karakter. Jangan hapus test ini — `OpiniSubmissionController` pernah kehilangan method `uniqueSlug()` sehingga seluruh kiriman opini 500. `SeoMetaTest` uses a private `headOf()` helper (a method named `head()` would clash with `TestCase::head()`) and a `userWithRole()` helper for role-gated pages.

## Ops

- Deploy: Render (`render.yaml`), two services. `konut-update` (web) runs `artisan serve` and its buildCommand runs `migrate --force`, `CategorySeeder`, `PageSeeder`, `storage:link --force`, `optimize`. `konut-worker` runs `queue:work` + `schedule:work` but **does not migrate** — deploy order matters. Without the worker, `RecordViewJob` and `posts:expire-flags` never run in prod.
- **The build command chains every step with `&&`**, so a failing seed aborts the whole deploy. The seeders run against an already-populated production DB, so they **must stay idempotent** (`firstOrCreate`/`updateOrCreate`) — `CategorySeeder` used to call `Category::create()` and its unique-slug violation aborted the deploy, leaving production on an old commit.
- `render.yaml` sets `PHP_CLI_SERVER_WORKERS=4`: `artisan serve` is single-threaded otherwise, and the synchronous Gemini call (up to 25s) would block the whole site. Also set `GEMINI_API_KEY` (and optionally `GEMINI_MODEL`/`GEMINI_DAILY_LIMIT`) in the Render dashboard — empty key hides the Tanya Berita widget.
- Full `DatabaseSeeder` (demo admin `admin@konutupdate.com` / `password`, plus editor/reporter) is **local-only**; production seeds just categories and pages.
- **`.env.production` is tracked in git** even though `.gitignore` lists it — it already holds the live Turnstile *site* key (public-safe) with an empty secret. Don't add secrets to it. `.env` itself is ignored and holds a real `GEMINI_API_KEY`.
- **Self-hosted server (bukan Render)?** `git pull` saja tidak cukup: `public/build` ada di `.gitignore`, jadi aset Vite harus dibangun ulang (`npm ci && npm run build`), dan `.env` server harus berisi `GEMINI_API_KEY` + `TURNSTILE_SECRET_KEY` (file `.env.production` hanya berisi placeholder kosong). Kalau `php artisan config:cache` aktif, ubah `.env` lalu `php artisan config:clear`. Verifikasi dengan `php artisan konut:doctor`.
- `livewire/livewire` `^4.3` is in `composer.json` but unused — no components, no views, no `wire:` directives (the only trace is a `livewire:navigated` listener in `resources/js/app.js`). Ignore it.
- Frontend is Alpine.js + jQuery/Bootstrap 5/DataTables/Swiper/Lucide; Tailwind 4 is compiled from `resources/css/*.css` with no `tailwind.config.js`.
- `resources/ai/panduan-konut-update.md` is runtime content for the AI guide, **not** a Blade view — it is never compiled by Vite and needs no `view:clear`.
